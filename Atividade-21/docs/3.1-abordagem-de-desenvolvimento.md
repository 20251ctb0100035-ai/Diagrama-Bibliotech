# 3.1 Abordagem de Desenvolvimento

O DoceAgenda é desenvolvido de forma **iterativa e incremental**. Cada ciclo produz uma seção deste documento, na ordem em que a análise exige: começa pela descrição geral (4.1), passa pelos requisitos e casos de uso (4.2.1 e 4.2.2), estrutura interna de dados e comportamentos (4.2.3 a 4.2.6) e encerra na prototipação das telas (4.2.7) e arquitetura (3.3).

No final de cada etapa, a nova seção é revisada contra as anteriores. Requisitos, casos de uso e entidades do banco de dados são verificados mutuamente para garantir consistência, registrando o histórico de alterações no repositório GitHub.

Esta abordagem serve especificamente a este projeto pois trata-se de um desenvolvimento individual com prazo letivo de um trimestre para entregar um sistema funcional a uma cliente real (Mariana). O modelo iterativo permite apresentar validações parciais à cliente ao fim de cada ciclo e identificar divergências na regra de negócio cedo, sem acumular erros para a entrega final. As reuniões diárias e papéis complexos do Scrum foram descartados pela natureza solo do projeto, mantendo-se apenas a lógica de entregas em ciclos curtos.
